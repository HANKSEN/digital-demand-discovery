# First-Principles Analysis

First-principles reasoning has the highest priority in this skill. Use it to prevent solution-led analysis from drifting away from the real problem.

## Core Questions

- What basic fact is true regardless of the requested solution?
- What real-world process currently fails, slows down, loses information, or creates risk?
- Who experiences the pain directly, and who pays for it indirectly?
- What information must be captured, trusted, transformed, shared, decided on, or acted on?
- What would improve if the problem were solved: speed, accuracy, cost, transparency, compliance, conversion, quality, scalability, or user experience?
- Why does this need a digital, automated, or intelligent solution instead of a process change?
- What is the simplest credible intervention?

## Surface Demand vs. Real Need

Translate requests like:

- "Build a CRM" into "Track relationships, follow-ups, deal state, and accountability."
- "Make a dashboard" into "Expose the right metrics at the right decision point."
- "Create an AI agent" into "Automate or augment a repeated judgment, search, writing, routing, or action loop."
- "Make a management system" into "Standardize workflow, permissions, state, data, and reporting."

## Red Flags

Pause and question the premise when:

- The user names a tool but not the pain.
- The solution requires many modules before any value is proven.
- The proposed system digitizes a broken process without improving it.
- Data ownership, input quality, or usage frequency is unclear.
- The user cannot say what decision or behavior should change.

## Output Pattern

Summarize first-principles analysis as:

```markdown
At the most basic level, this is not a request for [surface solution]. It is a need to [real change] because [current constraint]. The solution should first make [process/data/decision] reliable before adding [advanced capability].
```
